# Тесты

Запуск (из папки `server/` или `client/`):

```bash
npm test          # один прогон
npm run test:watch  # перезапуск при правках
```

## Сервер (`server/tests/`, vitest)

Тесты вызывают сервисы и контроллеры напрямую и работают с **настоящим PostgreSQL**, но с **отдельной базой**:

- Имя базы берётся из `DB_LINK` с добавлением `_test` (`anidale` → `anidale_test`). Пароль нигде не выводится.
- Перед прогоном схема в тестовой базе пересоздаётся (`prisma db push --force-reset`), перед каждым тестом таблицы очищаются.
- **Защита:** если имя базы не оканчивается на `_test`, тесты не запускаются (`tests/test-db.ts`). Рабочая база `anidale` тестами не затрагивается.
- Сокет (`@/index`) заменён заглушкой (`tests/setup.ts`), события можно проверять через `eventsOf(...)` из `tests/helpers.ts`.
- Redis в тестах по умолчанию выключен: кэш и лимиты проверяются запасными путями. Тесты `tests/redis.test.ts` включаются сами, если Redis доступен (адрес — `TEST_REDIS_URL` или `redis://127.0.0.1:6379`).
- Загрузку картинок (нативный модуль на Rust) тесты не используют: записи фото и видео создаются прямо в БД (`createPostImage`, `createVideo`).

Что покрыто: аккаунты (регистрация, подтверждение почты, ограничения для неподтверждённых, политика паролей, argon2id и перенос bcrypt-хешей, сброс и смена пароля с завершением сессий), посты (правка, закреп, архив, закладки, жалобы, репосты, просмотры, признак «сохранено»), мессенджер (отправка, чтение, ответы, реакции, закрепы, поиск, удаление, пересылка, архив и настройки диалога), фото и видео (сохранение, ленты, видимость архива), уведомления, истории, определение форматов файлов по содержимому, каталог аниме (доступ администратора, релизы, серии, расписание, жанры, скрытие черновиков и публичные файлы).

## Клиент (`client/src/**/*.test.ts(x)`, vitest)
Тесты без браузера: чистая логика (время, лимиты загрузки, ссылки в тексте, преобразование ответов сервера, уведомления) и стор мессенджера (сеть и вход заменены заглушками).

## E2E в браузере (`client/e2e`, Playwright)

Смоук-тесты проверяют, что страницы действительно рендерятся и не падают с ошибкой JS:

```bash
cd client
npx playwright install chromium   # один раз
npm run test:e2e                  # нужны запущенные server (:5000) и client (:5173)
```

Против собранного клиента: `E2E_BASE_URL=http://localhost npm run test:e2e`.
В CI эти тесты идут после сборки против `vite preview` на :4173.

## Скорость загрузки

Замер в браузере с отключённым кэшем и ограничением сети (как в DevTools). Сравнивайте только собранный клиент:
dev-сервер отдаёт сотни несжатых модулей, и его цифры ничего не говорят о продакшене.

```bash
cd client
npm run perf:feed                                  # http://localhost, fast4g, /feed
node scripts/perf-feed.mjs http://localhost slow4g
node scripts/perf-feed.mjs http://localhost fast4g /anime
```

Профили: `fast4g` (9 Мбит/с, 170 мс), `slow4g` (1.6 Мбит/с, 150 мс), `none`.

## Как писать новые тесты

- Нашли баг: сначала тест, который его воспроизводит, потом исправление.
- Серверные тесты берут пользователей и данные из `tests/helpers.ts` (`createUsers`, `createPost`, `resetDb` ...).
- Проверка «тест не пустой»: временно сломайте проверяемый код и убедитесь, что тест падает.
